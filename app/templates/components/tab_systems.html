Method 1: Enterprise Outbound Push Agent (Zero Ingress — Recommended) Outbound Only · No Open Ports Needed

Remote Linux nodes stream audit reports outbound directly to this central dashboard. Target servers do not need port 22 open, public IPs, or stored SSH credentials — works seamlessly across AWS, DigitalOcean, home Wi-Fi, and private VPCs.

Prerequisites:
✓ Target server has curl and bash installed.
✓ Root or sudo privileges to create cron jobs.
✓ Outbound network access from target node to Dashboard Port 8000.
curl http://127.0.0.1:8000/health
curl -sSL http://127.0.0.1:8000/install.sh | sudo bash -s -- --token [FETCHING_TOKEN] --server http://127.0.0.1:8000 --cron daily
Note: Replace 127.0.0.1 with your dashboard host's reachable LAN IP (e.g. 192.168.x.x) when running on external machines or VMs.
sudo lynislens-scan
Method 2: Native Lynis Enterprise Upload (Zero Third-Party Scripts) For Existing Lynis Deployments

Use the official Lynis binary's built-in enterprise protocol to upload reports directly using --upload. Ideal for DevOps fleets managed by Ansible, Puppet, or existing automation pipelines.

Prerequisites:
✓ Lynis installed on target (sudo apt install lynis or sudo dnf install lynis).
✓ /etc/lynis/ directory created.
✓ Reachable central server IP in upload_server to prevent Error (6) DNS failure.
sudo apt update && sudo apt install -y lynis && sudo mkdir -p /etc/lynis
curl -s http://127.0.0.1:8000/api/lynis/license/
Expected Output: OK. If this returns an error, verify the IP address and make sure Windows Firewall allows port 8000.
echo -e "\nupload=yes\nupload_server=http://127.0.0.1:8000/api/lynis/upload/\nlicense_key=[FETCHING_TOKEN]" | sudo tee -a /etc/lynis/custom.prf
sudo lynis audit system --upload
echo "0 3 * * * root /usr/sbin/lynis audit system --cronjob --upload > /dev/null 2>&1" | sudo tee /etc/cron.d/lynis-upload-audit
Method 3: Direct Agentless Remote SSH Auditing Inbound Port 22 · On-Demand Central Trigger

Audit remote Linux servers directly over SSH without installing persistent scripts or daemons. The dashboard connects via Port 22 on demand, executes privileged Lynis inspections, and streams results in real time.

Prerequisites & Practical Reality:
✓ Inbound Port 22 must be reachable on the target server from the dashboard host (firewalls/security groups must allow connection).
✓ SSH server running (sshd).
✓ Non-blocking Sudo: Sudo password prompts hang automated SSH execution. Configure passwordless sudo for Lynis below to prevent "Permission denied" or connection timeouts.
sudo systemctl enable --now ssh || sudo systemctl enable --now sshd
echo "$USER ALL=(ALL) NOPASSWD: /usr/sbin/lynis, /usr/bin/lynis, /opt/lynis/lynis" | sudo tee /etc/sudoers.d/99-lynislens-audit && sudo chmod 0440 /etc/sudoers.d/99-lynislens-audit
ssh <USERNAME>@<REMOTE_IP> "sudo lynis --version"

Click + Connect Remote Agent (top right) → Select Direct SSH → Enter Server IP, Username, Password / Key, and click Test SSH Connection.
